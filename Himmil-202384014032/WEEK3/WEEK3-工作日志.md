## 4. Key Implementation Notes

### 4.1 Unified Response Structure

`Result<T>` consistently returns three fields: `code`, `message`, and `data`. The success code is 200, while business failures reuse HTTP status codes (400/401/403/500). The frontend axios response interceptor only checks if `code === 200`; other cases trigger a pop-up and throw an error, avoiding repeated checks on every page.

`PageResult<T>` wraps four fields: `total`, `pageNum`, `pageSize`, and `list`, which can be reused for all paginated interfaces.

### 4.2 Centralized Management of Constants

`Constants` gathers scattered magic values in one place:

- Status codes and messages: `CODE_SUCCESS`, `CODE_UNAUTHORIZED`, `MSG_SERVER_ERROR`, etc.;
- JWT: request header `Authorization`, prefix `Bearer `, secret key, 24-hour expiry;
- Default pagination: 20 items for data, 15 for users, 10 for favorites, 10 for announcements, 10/15 for feedback, 20 for logs;
- Redis key prefixes: login failures, login lock, dashboard stats, chart cache, dictionary cache;
- File limits: avatar max 2MB and only JPEG/PNG, export max 5000 rows, import max 1000 rows.

### 4.3 MyBatis-Plus Compatibility Handling

The project baseline is Spring Boot 4.0.3, while the official MyBatis-Plus starter targets Spring Boot 3, and auto-configuration will fail under Spring Framework 7. Therefore:

1. Explicitly override `mybatis-spring` to 4.0.0 in dependencies;
2. Use `MybatisPlusConfig` to manually construct `MybatisSqlSessionFactoryBean`, explicitly configuring `DataSource`, `mapper/**/*.xml`, entity alias packages, camel case mapping, the logical delete field `deleted` (1 = deleted / 0 = normal), and the pagination plugin.

This way, we retain MyBatis-Plus's `BaseMapper` capabilities while bypassing the incompatibility issues with auto-configuration.

### 4.4 JWT and Passwords

`JwtUtil` uses jjwt 0.12.6, with token payloads containing `userId`, `username`, and `role`, and tokens expire 24 hours after issuance; `BcryptUtil` wraps Spring Security Crypto's BCrypt implementation, storing only the hash during registration and password changes.

### 4.5 Frontend Scaffolding

- `package.json` retains only the necessary dependencies: vue 2.6, vue-router 3, vuex 3, element-ui 2.15, echarts 5, axios 1.x; dev dependency is `@vue/cli-service` 5.
- `vue.config.js` proxies `/api` and `/uploads` to `http://localhost:8088`, with the frontend dev server listening on 8080 to avoid cross-origin issues during development.
- Include `package-lock.json` in version control to ensure a consistent dependency tree when switching machines.
